# External short-link sharing

Native external sharing tries to shorten every eligible link (see below), with no feature flag, build define, login or opt-out; a value saved by the removed Short Links toggle is ignored. Flutter web retains full URLs because the gateway does not allow its deployment origin. The gateway controls creation independently.

Only external video Copy/Share via, post-publish Share, a DM's Copy video URL and profile Share try shortening. Nostr events and DM message bodies retain the original canonical URL. Verified username subdomains keep their existing URL because they are outside the shortener destination grammar. First-party video IDs, full hex pubkeys and valid full npubs are preserved without truncation.

ShortLinkClient sends JSON to https://gateway.divine.video/api/links without an Authorization header. Transport and response reading share a two-second budget. Invalid mapping, quota, network, timeout and gateway-disabled responses fall back to the full URL. It refuses redirects, bounds responses to 4096 bytes and caches only exact validated successes, at most 100 per client. Provider disposal closes pending requests and clears cached mappings. No account state, feature-flag service or signing service is needed.

Repeated Copy/Share via events are dropped while the same action is pending. Action results from a dismissed modal cannot pop the source page or trigger a late platform share. Post-publish Share closes its sheet first, so its platform share can open up to two seconds after the tap while the link shortens. No new UI state or translations are introduced.

Receiving is already merged separately. This client behavior takes effect in the next app build; Android association changes also require a native store release. Public links redirect to canonical web URLs for clients without short-link handling. Disabling creation at the gateway preserves existing public redirects.

New video destinations use `https://divine.video/video/<naddr>` for addressable videos, carrying the real kind, author and d tag. Regular events or videos without a real d tag use `<nevent>`. The external share sheet, post-publish Share and a DM's Copy video URL shorten that complete destination. DM message bodies and protocol payloads keep the canonical reference without depending on the shortener. Copying from a message that carries only a legacy URL or an addressable citation copies its legacy `?author=` link, which the gateway may decline, in which case the full link is copied. Existing hex-ID, bare-d-tag, coordinate and `?author=<hex>` URLs remain readable; existing short mappings are unchanged. Deploy browser support for `/video/<naddr>` before distributing an app build that emits it.
