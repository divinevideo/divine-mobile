# Concord protocol

Pure Dart CORD protocol derivations, community-control authority and chat
folding. Stream carriers use kind 1059, with kind 20013 encrypted seals for chat
and kind 20014 plaintext signed seals for control. These are Concord streams,
separate from Divine's NIP-59 direct messages.

The owner is committed by the community ID. Control editions resolve delegated
roles, grant citations, channel definitions and bans before they can affect the
native room catalog or timeline. Entity versions retain accepted-head floors;
current-epoch snapshot attribution is tracked per entity. Shared synthetic
fixtures are generated by `packages/concord-core` in the bridge repository.
`control-parity.json` pins exact kernel heads, bans and completeness signals.

## Native application configuration

Without `CONCORD_INVITE_URL`, existing disposable POC rooms remain available.
When it is set, Rooms resolves the standard CORD-05 kind-33301 invitation and
shows only authenticated public channel definitions. Invalid invitations,
incomplete authority and banned membership fail closed, with no POC fallback.
A full control or lifecycle history window also keeps Rooms unavailable until
complete history can be established; the client cannot infer completeness from
a full window.
The bridge's approved import policy determines which Discord channels appear.
Private channel definitions are excluded from this native public-room view.

`CONCORD_RELAY_URL` selects the relay; a real invitation must be paired with its
community relay. `CONCORD_REPORTS_URL` selects the HTTPS signed-report endpoint
and defaults to the canonical Divine report service. Reports reuse the existing
Divine identity and NIP-98 authentication; they do not publish chat messages.

Room caches and read markers remain account-scoped. Control caches retain held
root epochs and accepted-head floors across refreshed invitations. Publication
pauses while authority is processing or the relay is catching up after reconnect.
Dissolution closes the community; a base-rotation signal requires reopening Rooms
with refreshed invite material. The chat timeline subscribes to the current root
epoch; displaying delivered chat history from retained prior epochs is not implemented.
Unconfirmed outbox messages retain their stable account/channel scope and can be
restored explicitly as drafts after rotation; old signed carriers are never retried
under the refreshed membership.

Source tests cover interoperability, authority rejection, cached moderation,
rotation/reopen, signer races and signed reports. Signed-device and production
round-trip acceptance remain separate release checks.
