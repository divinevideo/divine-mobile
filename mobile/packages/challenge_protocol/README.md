# Divine challenge protocol

Pure Dart implementation of the Divine challenge convention v1. This package
verifies signed Nostr sources, reduces a retained set into immutable projections,
and builds unsigned participant entry and withdrawal templates. It does not
contain networking, signing, key storage, widgets, or discovery enablement.

The canonical contract is divinevideo/divine-challenges at commit
5800cf866d7a5b1a1fb38201f58044e4dc024a3d. See
[test/fixtures/SOURCE.md](test/fixtures/SOURCE.md) for fixture provenance.
This is an application convention layered on Nostr, not a new standard NIP.

## Interfaces

- `NostrEvent` deeply copies the seven signed wire fields. `fromJson` verifies
  their ID and BIP-340 signature; `toJson` returns a fresh mutable wire copy.
  Construction alone never establishes authenticity.
- `parseChallengeEvent(Object?)` returns `ParseResult`: `ok` and a typed `value`
  on success, or the canonical error `code` and explanation on failure. It accepts
  decoded wire maps or immutable `NostrEvent` values and always verifies afresh.
- `reduceChallenge(events, coordinate, now, isVisible)` requires a current
  visibility callback and explicit Unix-second clock. Its immutable `ChallengeView`
  reports current rules, available entries, historical results, unresolved
  dependencies, and the current eligible result. `ActiveEntry.entry` contains the
  underlying entry projection; convenience getters expose its signed sources.
- `buildEntry(definition, video, createdAt)` and
  `buildWithdrawal(definition, entry, createdAt)` accept typed projections but
  reparse their signed sources. They return immutable `EventTemplate` values.
  Forged projection properties do not affect the templates.

All exposed collections are immutable; JSON conversion returns copies. API read
DTOs and mutable SDK events must remain separate from these signed projections.

## Caller responsibilities

The caller bounds transport bytes and retained batch size. Signed source records
are limited to 64 KiB of compact UTF-8 JSON; embedded snapshot strings count in
full. Unsigned outer extensions are ignored. The reducer authenticates oversized
retained definitions too, so a malformed newer revision cannot reopen old rules.
Snapshot JSON uses Dart's iterative decoder and only signed fields are copied;
snapshots' ordinary tags are never recursively parsed as challenge actions.

Current deletion, author blocks, video restrictions, media availability and
moderation belong in `isVisible`. Never use an unconditional allow policy for a
production feed. Render available projections only: raw signed result snapshots
are evidence of authorship, not permission to recover hidden playback. A hidden
pinned video does not promote a different revision, and a withdrawn or hidden
winner remains named without an available entry projection.

Before signing, fetch the current definition, check its revision and state,
verify the intended signer is the video/entry author, obtain explicit consent,
and preflight advertised relay limits. After signing, validate the complete
returned event and its signer against the reviewed template. Retry an uncertain
publication with the same signed event and ID. This package does not claim relay
acceptance, deadline receipt, complete discovery, or end-to-end native delivery.

## Compatibility and validation

Definitions use kind 31923; entries, withdrawals and results use kind 1111.
Supported signed video kinds are 21, 22, 34235 and 34236. Timestamp integers must
fit JavaScript's exact integer range. Title and winner-label limits count Unicode
grapheme clusters using the workspace's `characters` package. Byte limits count
UTF-8 bytes rather than Dart string length.

Timezone acceptance is a checked-in case-insensitive set generated by enumerating
638 ICU 78.3 system names with `ucal_openTimeZones`, then filtering each through
Node 26.4.0 `Intl.DateTimeFormat('en', {timeZone: name})`: 637 accepted names,
with `Factory` rejected. The audited runtime uses tz 2026a and Unicode 17.0.
This includes legacy aliases such as ACT, PST and SystemV/PST8PDT, preserving the
original signed spelling. No host ICU installation is needed at runtime. When
upgrading this table, repeat that enumeration/filter against the canonical
TypeScript runtime and rerun signed parser/replay comparisons. This finite audit
records the runtime used, not a promise about future timezone database versions.

Run with the repository's pinned Flutter 3.47.2 / Dart 3.13 toolchain:

```sh
cd mobile
flutter pub get --enforce-lockfile
cd packages/challenge_protocol
dart format --output=none --set-exit-if-changed .
dart analyze --fatal-infos
dart test
```

Tests verify pinned checksums before decoding, all 29 parser cases and all 22
replay scenarios in normal and reversed order, plus independently assembled
participant, mutation, Unicode, byte-boundary, snapshot, and replay cases.
Synthetic test signers generate fresh throwaway identities in memory; no signing
keys are stored in source. CI resolves the actual workspace and runs the same
package checks. Native repositories, UI, transports and release integration are
separate delivery work.
