# Routing

Use [GoRouter](https://pub.dev/packages/go_router) for declarative navigation with deep linking support.

---

## Route Configuration

### Use Sub-Routes
Structure routes logically, not flat:

```
✅ Good                    ❌ Bad
/                          /
/flutter                   /flutter
/flutter/news              /flutter-news
/flutter/chat              /flutter-chat
/android                   /android
/android/news              /android-news
```

Sub-routes ensure proper back navigation and URL readability.

### Use Hyphens in URLs
For multi-word paths:

```
✅ /user/update-address
❌ /user/update_address
❌ /user/updateAddress
```

## Type-Safe Routes

Routes are `GoRouteData` classes annotated with `@TypedGoRoute`, generated by
[go_router_builder](https://pub.dev/packages/go_router_builder). Most routes are
still hand-written; they migrate one module of `mobile/lib/router/routes/` per
PR (#3572, epic #9121), and every new route is typed. Hand-written `GoRoute` /
`ShellRoute` / `StatefulShellRoute` constructions under `mobile/lib` are frozen
per file by `mobile/scripts/check_hand_written_route_ceiling.sh`, a ceiling that
may only shrink, so a migrated module commits its lower ceiling with
`UPDATE_BASELINE=1 bash mobile/scripts/check_hand_written_route_ceiling.sh`.

The first migrated module, `account_deletion_recovery_routes.dart`:

```dart
part 'account_deletion_recovery_routes.g.dart';

List<RouteBase> accountDeletionRecoveryRoutes() => $appRoutes;

@TypedGoRoute<AccountDeletionRecoveryRouteData>(
  path: AccountDeletionRecoveryScreen.path,
  name: AccountDeletionRecoveryScreen.routeName,
)
class AccountDeletionRecoveryRouteData extends GoRouteData
    with $AccountDeletionRecoveryRouteData {
  const AccountDeletionRecoveryRouteData();

  @override
  Widget build(BuildContext context, GoRouterState state) =>
      const AccountDeletionRecoveryScreen();
}

// Navigation
const AccountDeletionRecoveryRouteData().go(context);
```

Run `dart run build_runner build --delete-conflicting-outputs` from `mobile/`
after changing a route class, and commit the `.g.dart` part. The rules below
are this repo's; each one exists because the generator's default breaks
something here.

- **One part file per module, `<Name>RouteData` classes.** A route class lives
  in its module's `*_routes.dart`. The module function returns the generated
  `$appRoutes`, so `app_router.dart` and its route order do not change. The
  `RouteData` suffix is deliberate: `<Name>Route` collides with widgets such as
  `VideoRecorderRoute` and with Flutter's own `Route` classes.
- **Paths and names come from the existing constants.** Annotate with the
  `RoutePaths` member or the screen's `path` / `routeName`, never a new literal.
  `RoutePaths` stays the one table of locations: redirects, the route parser
  and deep-link handling compare and return raw locations, and the layer
  ratchet keeps code below the UI from importing `lib/router/routes/`. The
  generator copies the value into the `.g.dart`, so the `Generated Files` check
  catches a constant that changed without a rebuild.
- **Path parameters are `String` fields.** Parse and validate them in `build`
  and render `RouteErrorScreen` with the route's own message for a bad value,
  as the hand-written routes do. A typed `int` path parameter is decoded with
  `int.parse` inside the generated route's redirect; go_router turns the throw
  into an error match, so a malformed URL lands on the generic unknown-path
  screen instead.
- **Query parameters keep their existing name.** The generator names a query
  parameter after its field in kebab-case, so `selectedPubkey` would become
  `selected-pubkey` and every existing link would stop being read. Annotate each
  one on its constructor parameter,
  `({@TypedQueryParameter(name: 'selectedPubkey') this.selectedPubkey})`: the
  annotation targets parameters only, and on the field the generator never
  sees it, so the name stays kebab-case with only an analyzer warning. Keep it
  a nullable `String`: a typed `bool` rejects any value but `true` or `false`,
  which sends the link to the same error screen as a bad path parameter.
- **`extra` is `final Object? $extra`.** The generated factory casts
  `state.extra as T`, and a restored `extra` arrives as a decoded `Map`. With a
  concrete type the cast throws inside the generated redirect, and a valid URL
  ends on the unknown-path error screen, which is the dead end #3335 forbids.
  Read it in `build` through `extraAs<T>` / `extraValue<T>`, as described under
  [Avoid Extra Parameter](#avoid-extra-parameter).
- **Riverpod is reached through the widget tree.** A `GoRouteData` has no
  `Ref`, so `build` and `redirect` read providers with
  `ProviderScope.containerOf(context, listen: false)`. With no `ProviderScope`
  above the router that throws, so a test of such a route pumps one.
- **Shells keep `notifyRootObserver: false` by hand.** `@TypedStatefulShellRoute`
  accepts the parameter, but go_router_builder 4.5.2 never reads it, so the
  generated shell notifies the root observers anyway. The shell module
  migrates last and rebuilds its `StatefulShellRoute` from the generated
  route's fields.

## Navigation Methods

Whatever the generic examples below show, never navigate with a literal path string in this repo: pass a `RoutePaths` constant or builder, or the screen's path builder. `mobile/scripts/check_literal_navigation_paths.sh` holds `mobile/lib` at zero (#3572).

### Prefer `go` Over `push`

| Method | Use When |
|--------|----------|
| `go` | Standard navigation (updates URL, manages back stack) |
| `push` | Expecting data back from route (dialogs, forms) |

```dart
// Standard navigation
const CategoriesRouteData().go(context);

// When expecting return value
final result = await const PickColorRouteData().push<String>(context);
```

### Prefer the Route Class
A typed route follows its path, its name and its parameters when they change:

```dart
// Good — typed route; the compiler checks its parameters
const AccountDeletionRecoveryRouteData().go(context);

// A route that is not typed yet: a RoutePaths constant or builder
context.push(RoutePaths.supportCenter);

// Bad — a literal path does not follow its route
context.go('/account-deletion-recovery');
```

### Use Extension Methods

```dart
// Good
context.push(RoutePaths.supportCenter);

// Bad
GoRouter.of(context).push(RoutePaths.supportCenter);
```

## Parameters

The examples from here on are generic. In this repo the path and name come
from `RoutePaths` and the screen constants, as described above.

### Path Parameters
For identifying specific resources:

```dart
@TypedGoRoute<ArticleRouteData>(
  name: 'article',
  path: '/article/:id',
)
@immutable
class ArticleRouteData extends GoRouteData with $ArticleRouteData {
  const ArticleRouteData({required this.id});
  final String id;

  @override
  Widget build(BuildContext context, GoRouterState state) {
    return ArticlePage(id: id);
  }
}

// Navigation
ArticleRouteData(id: 'abc123').go(context);
// URL: /article/abc123
```

### Query Parameters
For filtering or sorting:

```dart
@TypedGoRoute<ArticlesRouteData>(
  name: 'articles',
  path: '/articles',
)
@immutable
class ArticlesRouteData extends GoRouteData with $ArticlesRouteData {
  const ArticlesRouteData({
    @TypedQueryParameter(name: 'date') this.date,
    @TypedQueryParameter(name: 'category') this.category,
  });

  final String? date;
  final String? category;

  @override
  Widget build(BuildContext context, GoRouterState state) {
    return ArticlesPage(date: date, category: category);
  }
}

// Navigation
ArticlesRouteData(date: '07162024', category: 'all').go(context);
// URL: /articles?date=07162024&category=all
```

### Avoid Extra Parameter
Don't use `extra` for passing objects - breaks deep linking and web.

In this repo `extra` is a **warm-start cache only**: every route resolves from
path parameters, query parameters and repositories, and no route builder may
dead-end because `extra` was absent (#3335). Read it through `extraAs<T>` /
`extraValue<T>` from `mobile/lib/router/routes/route_extras.dart` — `extra` can
arrive as `null`, or as decoded JSON (a plain `Map<String, dynamic>`) rather
than the type that was passed, so a raw cast crashes the builder. Within one
session the router keeps typed objects when it re-reads its own route state,
through `RouteExtraCodec` (#9292); nothing carries them across a cold start or
a link. The per-route inventory of what each hint saves, and what a URL-only
entry falls back to, lives in
[`mobile/docs/DEEP_LINK_URL_REFERENCE.md`](../../mobile/docs/DEEP_LINK_URL_REFERENCE.md#route-state-and-extra).

```dart
// Bad - breaks deep linking
@TypedGoRoute<ArticleRouteData>(
  name: 'article',
  path: '/article',
)
class ArticleRouteData extends GoRouteData with $ArticleRouteData {
  const ArticleRouteData({required this.$extra});
  final Article $extra;  // A typed object in extra - bad!
}

// Good - pass ID, fetch in page
@TypedGoRoute<ArticleRouteData>(
  name: 'article',
  path: '/article/:id',
)
class ArticleRouteData extends GoRouteData with $ArticleRouteData {
  const ArticleRouteData({required this.id});
  final String id;  // ID can be in URL

  @override
  Widget build(BuildContext context, GoRouterState state) {
    return ArticlePage(id: id);  // Page fetches article
  }
}
```

## Redirects

### Global Redirects
For authentication:

```dart
GoRouter(
  initialLocation: '/',
  redirect: (context, state) {
    final status = context.read<AppBloc>().state.status;
    if (status == AppStatus.unauthenticated) {
      return const SignInRouteData().location;
    }
    return null;  // No redirect
  },
  routes: $appRoutes,
);
```

### Route-Level Redirects
For specific route protection:

```dart
@TypedGoRoute<PremiumRouteData>(
  name: 'premium',
  path: '/premium',
  routes: [
    TypedGoRoute<PremiumShowsRouteData>(
      name: 'premiumShows',
      path: 'shows',
    ),
  ],
)
@immutable
class PremiumRouteData extends GoRouteData with $PremiumRouteData {
  @override
  Widget build(BuildContext context, GoRouterState state) {
    return const PremiumPage();
  }

  @override
  String? redirect(BuildContext context, GoRouterState state) {
    final status = context.read<AppBloc>().state.user.status;
    if (status != UserStatus.premium) {
      return const RestrictedRouteData().location;
    }
    return null;
  }
}
```

**Note:** Parent redirects execute first, so one redirect on a parent can protect all sub-routes.

## Nested Routes Example

```dart
@TypedGoRoute<TechnologyRouteData>(
  name: 'technology',
  path: '/technology',
  routes: [
    TypedGoRoute<FlutterRouteData>(
      name: 'flutter',
      path: 'flutter',
      routes: [
        TypedGoRoute<FlutterNewsRouteData>(
          name: 'flutterNews',
          path: 'news',
        ),
      ],
    ),
  ],
)
```

Results in:
- `/technology`
- `/technology/flutter`
- `/technology/flutter/news`

Each level supports proper back navigation.
